POST /check-email Get available login methods for an email
public ▾
Request body
{
  "email": "pulkit@example.com"
}
Use case
// Call before showing any login UI.
// Frontend renders ONLY available methods.
// Never call this after failed /login —
// availableMethods is returned there too.
Response · 200 (found)
{
  "exists": true,
  "availableMethods": [
    "password",  // if password !== null
    "google",    // if authProviders has google
    "otp"        // always present
  ]
}
Response · 200 (not found)
{
  "exists": false,
  "availableMethods": [],
  "message": "No account found. Please sign up."
}
Password Auth
POST /login Login with email + password
authLimiter public ▾
Request body
{
  "email":    "pulkit@example.com",
  "password": "secret123"
}
Error responses
// No account:
{ "code": "INVALID_CREDENTIALS" }

// No password set (OTP/Google user):
{
  "code": "INVALID_CREDENTIALS",
  "availableMethods": ["otp"]
}

// Wrong password:
{
  "code": "INVALID_CREDENTIALS",
  "availableMethods": ["password", "otp"]
}
Response · 200
{
  "success":      true,
  "accessToken":  "eyJ...",
  "refreshToken": "eyJ...",
  "user": {
    "id":    "...",
    "name":  "Pulkit Gaur",
    "email": "pulkit@example.com"
  }
}
Security note
// All failures return same vague message.
// Never reveals if email exists or
// which provider they signed up with.
// Frontend reads code field, not message.

Google OAuth 2.0
GET /google Redirect to Google consent screen
public ▾
Usage
// Open in browser — not curl
// Redirects to accounts.google.com
// scope: profile, email
window.location.href =
  '/api/auth/google'
Flow
// 1. User approves on Google
// 2. Google redirects to /google/callback
// 3. Passport exchanges code for profile
// 4. findOrCreate user in DB
// 5. addProvider('google')
// 6. Redirect to CLIENT_URL/auth/success
//    ?accessToken=xxx&refreshToken=yyy
GET /google/callback Google OAuth callback — handled by Passport
public ▾
Note
// Do not call this directly.
// Google redirects here automatically.
// On success → googleCallback controller
// On failure → /google/failure
Success redirect
// Redirects to:
`${CLIENT_URL}/auth/success
  ?accessToken=eyJ...
  &refreshToken=eyJ...`

// Production: use httpOnly cookies instead
Token Management
POST /refresh Exchange refresh token for new token pair
authLimiter public ▾
Request body
{
  "refreshToken": "eyJ..."
}
Rotation behaviour
// Old refresh token is invalidated
// New access + refresh pair issued
// DB match check prevents reuse after
// rotation — detects stolen tokens
Response · 200
{
  "success":      true,
  "accessToken":  "eyJ...",  // new
  "refreshToken": "eyJ...",  // new
  "user": { ... }
}

GET /me Get current authenticated user

// 1. Reads Authorization header

Password Reset
POST /forgot-password Send password reset link to email
authLimiter public ▾
Request body
{
  "email": "pulkit@example.com"
}
Token generation
// crypto.randomBytes(32) → rawToken
// sha256(rawToken) → stored in DB
// rawToken → email link only
// Expires in 15 minutes
Response · 200 (always)
{
  "success": true,
  "message": "If an account with that
    email exists, a password reset
    link has been sent."
}
// Identical whether email exists or not
// Never confirms email registration
POST /reset-password Set new password using reset token
authLimiter public ▾
Request body
{
  "email":       "pulkit@example.com",
  "token":       "cd995efd...",  // raw
  "newPassword": "newSecret123"
}
Side effects
// sha256(token) === DB hash ✓
// user.password = bcrypt(newPassword)
// user.addProvider('local') pushed
// passwordResetToken = null (single-use)
// Issues tokens → logs in immediately
Response · 200
{
  "success":      true,
  "accessToken":  "eyJ...",
  "refreshToken": "eyJ...",
  "user": { ... }
}
// After this, /check-email returns
// 'password' in availableMethods
Token Reference
Token Expiry Storage Purpose
accessToken 15 min Memory / Authorization header Authenticate every API request via protect middleware
refreshToken 7 days DB + client storage Exchange for new token pair at /refresh. Rotated on each use.
OTP code 10 min DB (plaintext) Passwordless login. Single-use. Cleared after verify-otp.
passwordResetToken 15 min DB (sha256 hash only) Password reset. Raw token in email only. Single-use.
Rate Limits

globalLimiter

100 requests / 15 min per IP
Applied to all routes

authLimiter

10 requests / 15 min per IP
/login /signup /refresh /forgot /reset

otpLimiter

3 requests / 10 min per IP
/send-otp /verify-otp

No limit

/logout /check-email /health
/google /google/callback

Error Codes
INVALID_CREDENTIALS
Login failed — email not found, no password set, or wrong password.
→ read availableMethods[]
400 Bad Request
Missing required fields or validation failure (e.g. password too short).
→ check request body
401 Unauthorized
Invalid/expired access token on protected routes.
→ call /refresh
Invalid or expired OTP
OTP doesn't match, already used, or 10 min window passed.
→ call /send-otp again
Invalid or expired reset token
Token mismatch, already used, or 15 min window passed.
→ call /forgot-password again
Refresh token reuse detected
Refresh token used after rotation — possible token theft.
→ force re-login
Login Flows
Password login
POST /check-email → show password field → POST /login → store tokens
OTP login
POST /send-otp → check email → POST /verify-otp → store tokens
Google OAuth
GET /google → Google consent → GET /google/callback → redirect with tokens
Forgot / reset password
POST /forgot-password → check email inbox → POST /reset-password → logged in + 'password' unlocked
Token refresh
401 on any request → POST /refresh → new token pair → retry original request
